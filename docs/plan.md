# Updated Leaf Physics Test Plan — Isaac Sim 4.5

## Goal

Compare two approaches for interactive tomato leaves:

1. **PhysX deformable leaf**
2. **Rigid-link + D6 + skinning leaf**

A key requirement is now explicit:

> The leaf must eventually be able to hang from and move with a **dynamic petiole/branch chain**, without requiring the leaf itself to be attached to the world or to a kinematic body.

The deformable body will therefore be tested not only in isolation, but also while attached to a **dynamic rigid body belonging to the branch/petiole articulation**.

---

# Track A — PhysX Deformable Leaf

## D0 — Basic Deformable Strip

Purpose:

Verify that a thin deformable body behaves correctly before introducing attachments or complex geometry.

Setup:

```text
fixed region
│
██████████████████
simple thin strip
```

Test:

* gravity;
* sag;
* elastic response;
* damping;
* simulation stability.

Use a simple regular mesh and a thin volumetric representation.

Check:

* timestep;
* mesh resolution;
* thickness;
* Young's modulus;
* damping.

---

## D1 — Contact Test

Add a rigid sphere or capsule.

```text
        ●
        ↓

██████████████████
```

Move the object slowly into the deformable.

Measure:

* maximum deformation;
* tip displacement;
* penetration/contact stability;
* recovery;
* oscillation.

Keep the interaction initially quasi-static.

# D2 — Dynamic Rigid Attachment

### This test is now mandatory before using the real leaf geometry.

Purpose:

Verify that a deformable leaf can be attached to a **dynamic rigid body** rather than directly to the world.

Setup:

```text
WORLD
  │
 joint
  │
██████████
dynamic rigid link
      │
      │ PhysX attachment
      ▼
 ┌─────────────┐
 │ deformable  │
 │    leaf     │
 └─────────────┘
```

The rigid anchor must:

* have normal rigid-body dynamics;
* respond to gravity;
* be movable by a joint;
* **not be kinematic**.

The deformable body must follow this rigid body through the PhysX deformable-rigid attachment.

---

## D2.1 — Gravity-only test

Let the rigid link and deformable leaf hang freely.

Expected behaviour:

```text
anchor
   ╲
    ╲
     █
      ╲
       ╲____ leaf
```

Check that:

* the attachment remains stable;
* the deformable does not detach;
* no vertices explode;
* the leaf mass affects the dynamic rigid system plausibly.

---

## D2.2 — Passive joint motion

Use a D6 or revolute joint connecting the rigid anchor to another rigid body.

```text
rigid
  │
 D6
  │
rigid anchor
  │
attachment
  │
deformable leaf
```

Allow the system to move passively under gravity.

Verify that:

* the rigid link rotates;
* the deformable follows;
* the attachment remains stable during motion.

---

## D2.3 — Driven motion

Move the rigid petiole/anchor slowly.

For example:

```text
0°
↓
10°
↓
-10°
↓
0°
```

Observe whether the deformable leaf follows smoothly.

The purpose is to detect:

* attachment lag;
* excessive deformation near the attachment;
* unstable constraints;
* numerical explosions.

---

## D2.4 — Contact while hanging

This is the most representative isolated experiment.

```text
branch/link
      ╲
       ╲
        █ anchor
         ╲
          ╲____ deformable leaf
               ↑
               ● robot/object
```

Press a sphere against the hanging leaf.

The leaf should:

1. move together with the petiole;
2. locally deform under contact;
3. potentially cause some motion of the petiole;
4. recover when contact is removed.

This tests the complete coupling:

```text
external contact
       ↓
deformable leaf
       ↓
attachment
       ↓
dynamic rigid petiole
       ↓
D6 joint
       ↓
branch
```

This is the architecture we ultimately care about.

Introduce the natural leaf curvature generated by the existing leaf pipeline.

Important distinction:

```text

        +
dynamic elastic deformation
```

The deformable should begin from a biologically plausible leaf shape and then respond locally to gravity/contact.

# Track B — Rigid Links + D6 + Skinning

## J0 — Simple 3-Link Leaf

Create:

```text
root
 │
 ●━━━●━━━●
    D6  D6
```

Each link:

* rigid body;
* simple box/capsule/convex collider.

Disable collision between adjacent links.

---

# J1 — Tune D6 Behaviour

Configure:

* bending stiffness;
* bending damping;
* twist stiffness;
* angular limits;
* rest pose.

Target behaviour:

```text
contact
   ↓
bend
   ↓
small recovery oscillation
   ↓
rest
```

Avoid excessively high drive stiffness.

---

# J2 — Add Continuous Visual Mesh

Skin one continuous visual leaf to the physical links.

```text
physical:

[====]-[====]-[====]


visual:

╭──────────────────╮
│ continuous leaf  │
╰──────────────────╯
```

Use blended skinning weights around joint regions.

Avoid:

```text
100% bone A | 100% bone B
```

Prefer gradual transitions.

# Possible Final Architecture

If the deformable approach works reliably, it can serve as a reference model:

```text
Deformable leaf
       ↓
measure realistic response
       ↓
derive target deformation
       ↓
tune D6 + skinning model
       ↓
deploy lightweight model
```

The final plant could potentially use three interaction levels:

```text
Level 0
visual leaf only

Level 1
visual leaf + rigid collider

Level 2
D6 + skinned interactive leaf
```

while deformables remain primarily a validation/reference mechanism.

---

# Critical Implementation Detail

The deformable leaf is **not itself a link of the articulation**.

The correct architecture is:

```text
                    ARTICULATION

rigid ── D6 ── rigid ── D6 ── rigid petiole
                                     │
                                     │ PhysX attachment
                                     ▼
                               deformable leaf
```

Not:

```text
rigid ── D6 ── deformable
                  ❌
```

The attachment connects the deformable to an existing **dynamic rigid link**.

No kinematic body should be required for the final architecture.

---

# Updated Recommended Order

The implementation sequence should now be:

```text
D0  basic deformable strip
 ↓
D1  contact with sphere
 ↓
D2  deformable attached to dynamic rigid link
 ↓
D2.1 gravity test
 ↓
D2.2 passive joint motion
 ↓
D2.3 driven joint motion
 ↓
D2.4 contact while hanging
 ↓
D3  real tomato leaf contour
 ↓
D4  natural initial curvature
 ↓
D5  material/solver tuning


J0  3-link rigid leaf
 ↓
J1  D6 tuning
 ↓
J2  skinning
 ↓
J3  real tomato leaf
 ↓
J4  integration with dynamic petiole


        ↓

C0  isolated comparison
 ↓
C1  hanging-leaf comparison
 ↓
choose / calibrate final runtime model
```

The **go/no-go milestone for deformables is D2.4**.

If a deformable leaf can remain stable while:

* attached to a dynamic petiole;
* hanging under gravity;
* moving through a D6 articulation;
* receiving external contact;

then the architecture is genuinely relevant to the final tomato plant.

If D2.4 is unstable or prohibitively expensive, there is little reason to invest heavily in more complex deformable leaf geometry, and development should move primarily toward the D6 + skinning solution.
